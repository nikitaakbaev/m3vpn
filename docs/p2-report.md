## Теги и избранное

- `servers.favorite` — отдельный флаг, миграция для существующих БД;
- таблица `server_tags(server_id, tag)`;
- избранное показывается звездой в строке и отдельным фильтром;
- теги вводятся через запятую в диалоге, нормализуются в нижний регистр,
  дубликаты удаляются, максимум 8 тегов по 32 символа;
- теги участвуют в поиске;
- избранные серверы поднимаются выше в группе;
- счётчик избранного в тулбаре.

Tauri-команды: `set_server_favorite`, `set_server_tags`.

## История пинга

Таблица `ping_samples` использовалась и раньше, но теперь в неё пишется
каждый результат `update_latency`.

Для каждого сервера возвращаются последние 20 замеров за 6 часов:

- `history` — точки `ts`, `latencyMs`, `ok`;
- `jitterMs` — средняя абсолютная разница между соседними успешными
  замерами;
- `lossPercent` — доля неуспешных замеров.

В строке сервера:

- sparkline по успешным замерам;
- красный badge потерь, если loss > 0;
- tooltip с jitter и loss.

Старые замеры удаляются раз в цикл пинга (retention 7 дней).

## Traffic-aware auto-switch

Перед автопереключением приложение спрашивает Clash API front-прокси
(`/connections`) и считает скорость по приросту `uploadTotal + downloadTotal`
между проверками пинга.

- настройка `select.traffic_guard` — включена по умолчанию;
- порог `select.traffic_guard_kbps` — 256 КБ/с по умолчанию;
- если скорость выше порога, сервер не меняется;
- пользователь один раз получает уведомление «Переключение отложено:
  идёт активный трафик»;
- ручная кнопка «В самый быстрый» игнорирует защиту;
- если front API недоступен, переключение не блокируется.
